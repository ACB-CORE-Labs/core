# B2.5 — Audit-Finding Retries & Pipeline Dispatch

**Zone / stack:** B2.5 (macro layers M3/M2) | **Tier:** B | **Batch:** 2 (ADR-0051–0100)
**Members:** ADR-0088, ADR-0089, ADR-0090 | **Card author:** Claude (Tier B audit agent, Sonnet 5)
**`verified_at` SHA:** `cbfc8ccb` (`cbfc8ccbf7fe503ab31abe7aedbb1973ba7d7b4d`, 2026-07-28)

All three ADRs are dated 2026-05-20/21 and answer specific numbered findings ("Finding 2", "Finding 4", "Findings 6+7") from what their own text calls "the 2026-05-20 second-opinion audit" — a review whose source document could not be located in `docs/` (see the provenance note at the end of this intro). All three follow one shared, explicitly-named house pattern: land a flag-gated, default-off, byte-identical-when-off change, and defer the default flip to a later, separately-validated step. All three delivered on that pattern's first half — every flag exists, defaults off, and is CI-pinned null-lift-identical — but none has been flipped, and a corpus-wide, ratified register (`docs/specs/flag_register.md`, Authority R-3/R-4, ruled 2026-07-28) independently names `unified_ingest` (ADR-0090) and `realizer_grounded_authority` (ADR-0088) as two of its four clearest instances of "accumulated hesitancy": shipped complete, off "to preserve byte-identity," with **no criterion recorded** for what would end that preservation. ADR-0089 is a different shape again — its Phase C1 (observability substrate) is live and unconditional (no flag at all), but Phase C2 (the actual multi-node compound-intent *dispatch* the ADR's title promises) was never built: no `compound_intent_dispatch` config flag exists, and `core/capability/reporting.py`'s own flag catalog records this explicitly as `"substrate_shipped_flag_missing"`. ADR-0089's compound classifier decomposes a prompt by calling `classify_intent()` — the pre-existing `_RULES`/`IntentTag` regex router from ADR-0018, independently identified as the true routing mechanism by Batch 1's B6 card — once per clause; it composes the existing router rather than bypassing or duplicating it. ADR-0090's "unified ingest" is unrelated in scope to ADR-0002/ADR-0012's durable, governed `core_ingest/` ingest layer (Batch 1, B1) — it operates entirely inside the transient runtime-ingest half of that ADR-0002-declared dual-path architecture, reconciling only the `probe_ingest`/`commit_ingest` split within `ChatRuntime.chat()`. No contradiction found, but the name "ingest" is reused across two structurally distinct mechanisms without cross-reference between the ADRs, a minor Semantic Rigor tension noted below.

**Provenance note on "the 2026-05-20 second-opinion audit."** All three ADRs, and the commit that introduced ADR-0088/0089 (`8b51813c`, "unblock Findings 2 + 4"), refer to this audit only by date and finding number, never by a filename. `docs/EVAL_AUDIT_2026-05-20.md` — the only doc dated 2026-05-20 found in the tree — is a different, unrelated audit (eval-lane cross-provider triage, no "Finding N" numbering, no realizer/compound-intent/ingest content). `docs/pack_inventory_2026-05-21.md` corroborates that the audit was real and produced seven shipped PRs (#76→#83) but does not name or link a source document either. Git history confirms the shipped PRs (#76 surface-resolver, #81 the two ADRs, #85–#91 the implementation PRs, #95 for ADR-0090) but no commit adds a standalone audit report. Conclusion: the audit appears to have been an ephemeral (chat-session or PR-review) exercise whose findings were transcribed directly into these three ADRs' Context sections and never persisted as an independent document — not a defect of these ADRs specifically, but a citation that cannot be independently verified beyond the ADRs' own restatement of it.
