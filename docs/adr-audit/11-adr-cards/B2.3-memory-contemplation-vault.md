This zone picks up the vault-recall lineage exactly where Batch 1's B2 card (`docs/adr-audit/11-adr-cards/B2-agency-tooluse-learning-vault.md`) left ADR-0019, and follows the inter-session-memory / contemplation arc that grew out of it three days later. ADR-0054 is confirmed **not** a continuation of ADR-0019's own Stage 2/3 gating scheme — it closes a different, adjacent gap (the per-call deque→ndarray conversion cost Stage 1 left behind, plus a genuinely new batched-query API) that ADR-0019 never specified, while ADR-0019's own Stage 2 (norm-bucketed pre-filter) and Stage 3 (layered store) remain exactly as correctly untriggered as Batch 1 found — no code implementing either exists at this SHA. ADR-0055/0056/0057 are a clean phased arc (parent → Phase C1 → Phase C2) that builds a genuinely well-executed, doctrine-disciplined proposal/review/replay-equivalence pipeline for letting the system nominate its own knowledge, gated at every step by mechanically-enforced human review; the code matches the ADRs' pseudocode almost line for line, including the canonical vault→pack→corpus probe order and the five-gate eligibility check. Its headline safety claim, "self-interrogation without self-ratification," is not merely doctrine: `ContemplationFinding.__post_init__` and `ContemplationRun.__post_init__` raise `ValueError` on any non-`SPECULATIVE` construction, and every path that could turn a finding into standing knowledge (`accept_proposal`, `apply_composition_claim`) requires an explicit, named human reviewer. This is the one place in this zone where the audit went looking for the kind of silent safety-predicate bypass Batch 1's A5 stack found repeatedly, and did not find one.

# ADR-0054 — Vault Recall: Matrix-Cache Indexing + Batched API; Holdout Split Wired

## 1. Content summary

- **Decision made:** two bundled, doctrine-aligned items. **Part 1:** add a lazily-built matrix cache (`VaultStore._matrix_cache`) so the deque→ndarray conversion `vault_recall` pays on every call is paid once per mutation instead, and add a true batched-query API (`algebra.backend.vault_recall_batch`, `VaultStore.recall_batch`) scored via the same diagonal CGA metric, component-serial for bit-identity with the single-query path. **Part 2:** wire `--split holdout` into the official eval runner (`evals/framework.py`, `core/cli.py`), routing plaintext holdouts through the standard `run_lane` path while leaving sealed/encrypted holdouts to `holdout_runner.run_holdout`'s aggregate-only contract.
- **Alternatives explicitly rejected:** none named as a two-option choice; the ADR instead reiterates standing doctrine constraints (no approximate search, no hidden normalization/hot-path repair, no shared mutable state across recalls) as the boundary the new cache and batch API must not cross.
- **Artifacts the ADR claims will exist:**
  - `VaultStore._matrix_cache: np.ndarray | None`, lazily rebuilt, invalidated on `store()` / `reproject()` / `_rebuild_index()`
  - `vault_recall`'s new optional `prebuilt_matrix=` kwarg
  - `algebra.backend.vault_recall_batch(matrix, queries, top_k) -> list[list[(int, float)]]`
  - `VaultStore.recall_batch`
  - `evals/framework.py::LaneInfo.holdout_cases_path`
  - `--split` choices extended to `{"dev", "public", "holdout"}` in `core/cli.py`
  - `tests/test_vault_recall_indexing_batch.py` (21 tests) and `tests/test_eval_holdout_split.py` (10 tests)

## 7. Necessity / generality

1. **Necessity:** the matrix cache is genuinely necessary — it closes a real, measured, repeated cost (Stage-1-class conversion overhead) that would otherwise recur on every recall against a growing vault. The batched-query API's necessity is unproven-by-use today: it is correct and available, but nothing in the system currently needs to issue more than one query per recall.
2. **Reducibility:** same relationship as ADR-0019 — this is not a new capability so much as a correct, efficient realization of the CGA inner product's bilinearity, applied to eliminate a Python-level conversion tax rather than to accelerate the algebra itself.
3. **Extensibility:** the clearest candidate in this zone. ADR-0056's `contemplate()` loop (`teaching/contemplation.py`) issues its vault probes one sub-question at a time, synchronously — a design choice made deliberately (ADR-0056 Call 4) to preserve determinism, not because batching was unavailable. `vault_recall_batch`/`VaultStore.recall_batch` could batch multiple sibling sub-question probes within one `contemplate()` pass without touching Call 4's determinism requirement (batching preserves per-query results and order identically to serial calls, by the ADR's own bit-identity design) — today these two ADRs, built three days apart in the same zone, do not know about each other's relevant surface.

**Necessity/generality axis:** irreducible (matrix cache); generalization-candidate (batched API ↔ ADR-0056's sub-question probe loop — a same-zone consolidation opportunity that has not been taken).

# ADR-0080 — Contemplation Loop: self-interrogation without self-ratification

**Audit ID (if a numbering collision):** — | **Family (if phased):** —

## 1. Content summary

- **Decision made:** introduce a deterministic, sandboxed contemplation loop distinct from the existing learning boundary (reviewed corrections → `ReviewedTeachingExample` → `PackMutationProposal` → review). Its first phase is read-only and report-driven: it consumes explicit substrate snapshots/reports (starting with `frontier_compare` benchmark JSON) and emits `ContemplationFinding` records, every one of which is `SPECULATIVE` by construction. The doctrinal core: "Self-contemplation may interrogate the current learned substrate and emit evidence-bearing SPECULATIVE findings. It may **not** ratify, promote, or apply its own conclusions." Five hard invariants are named: no self-ratification, no pack mutation, replay determinism, evidence-bearing output only, read-only first wave (no repo crawling, no external calls, no live mutable-state inspection).
- **Alternatives explicitly rejected:** letting the model "think about its current knowledge, generate new statements, and then treat those statements as learned" — named directly as "recursive self-confirmation," the failure mode the whole ADR exists to prevent.
- **Artifacts the ADR claims will exist:**
  - `core/contemplation/{schema.py, snapshot.py, runner.py, miners/frontier_compare.py}`
  - `ContemplationFinding` dataclass, hard-typed `SPECULATIVE`-only
  - substrate-snapshot hashing, canonical JSON, stable finding/run hashes
  - a `frontier_compare` report miner (one finding per failed benchmark case)
  - unit tests proving no promotion, no mutation, deterministic replay, evidence-requirement

## 3. Liveness / integration

- **Operator-invoked path (`core/contemplation/__main__.py`):** live — a CLI entry point exists for running the miner against an explicit report path, exactly as Phase 1 specifies.
- **Idle-loop path:** also live, but gated. `chat/runtime.py:1074-1120` wires `core.contemplation.runner.run_contemplation`/`write_contemplation_run` into the always-on idle tick under `config.contemplate_frontier_during_idle` (default `False`, confirmed in `core/config.py:360`) — when enabled, the idle loop autonomously mines the frontier-compare frontier into persisted `SPECULATIVE` findings under `<engine_state>/contemplation_runs/`, best-effort (a mining failure degrades to "0 findings this beat," never crashes the loop), idempotent per frontier (a re-mined frontier is not re-persisted). Findings are read-only exposed via `workbench/readers.py`'s `list_contemplation_runs`/`read_contemplation_run` (`GET /contemplation/runs` in `workbench/api.py:262-278`) — confirmed to be a pure read/display surface with no write-back path.
- **Self-ratification bypass check (the audit's specific brief):** grepped every call site of `accept_proposal` and `apply_composition_claim` (the two corpus/pack-mutating functions in this general vicinity of the codebase) — both require an explicit human `reviewer`/operator identity and neither is ever called from `core/contemplation/` or from the idle-loop wiring. No path was found by which a `ContemplationFinding` becomes a ratified claim without passing through the ordinary, separately-reviewed `finding → review → coherence judgment → pack mutation proposal → ratification` chain the ADR names. **This is the one place in this zone the audit specifically went looking for a silent bypass of a safety predicate (the pattern Batch 1's A5 stack found repeatedly for other predicates), and did not find one.**
- **Sabotage test:** remove the `epistemic_status is not EpistemicStatus.SPECULATIVE` guard in `schema.py` — nothing downstream would immediately misbehave (no caller currently constructs a non-`SPECULATIVE` finding), so on a narrow reading this guard is *currently* redundant with actual call-site behavior. But it is the single mechanical backstop against a *future* miner (the ADR's own "Deferred follow-up" section anticipates several: pack-coverage-gap miners, contradiction-candidate miners, derivable-relation miners) accidentally or maliciously constructing a `COHERENT` finding — removing it converts a hard invariant into an unenforced convention. This is exactly the kind of predicate the sabotage test is designed to catch, and it correctly reads as load-bearing *for the invariant's own stated purpose*, not decorative.
- **Liveness axis:** live — both the operator-invoked and idle-loop paths are real and reachable (the idle-loop path gated off by default, per the zone's now-familiar pattern), and the self-ratification guard is confirmed genuinely load-bearing rather than decorative.
