## 0. Why this is one stack

Two ADRs, filed four days apart, accepted the same day (2026-05-22), that do exactly one thing each: emit ADR-0091 Domain Pack Contract v1 fields into one pack manifest so that `core capability ledger` prints a `status: reasoning-capable` row for a domain. ADR-0100 §Context states the relationship in its own words: *"This ADR applies the ADR-0097 ratification template to the physics domain."* ADR-0100's `Depends on:` list carries ADR-0097 directly.

They are one stack not because they share a module — they share **nothing but a template** — but because they are the *first two instances of the capability-ledger ratification act*, and the ledger row is a single shared artifact. ADR-0097 is the template author; ADR-0100 is the proof the template generalizes ("Demonstrates the ADR-0091 contract is not math-only" — ADR-0100 §Consequences). Auditing either alone cannot answer whether the template's bar is a real bar; auditing both together can, because the same nine predicates are applied to two disjoint vocabularies and produce the same verdict by the same route.

Three sibling ADRs (0101 `systems_software`, 0102/0103 `hebrew_greek_textual_reasoning`) apply the identical template and are scheduled in Batches 2/3 respectively; 0102/0103 already carry `AA-75`.

## 1. Stack-level claim

> **`mathematics_logic` and `physics` are `reasoning-capable` domains: each is backed by a pack that satisfies all nine ADR-0091 Domain Pack Contract predicates, and `core capability ledger` emits a ratified row saying so.**

Both member ADRs state falsifiable invariants in their own §Invariant sections, so this stack is tested the way FA-1 tested ADR-0005/0015.

- **Pre-registered criterion (ADR-0097 §Invariant, verbatim):** *"`mathematics_logic_reasoning_capable_ledger_row` — running `core capability ledger` emits a row for `domain_id: mathematics_logic` with `status: reasoning-capable`, provenance pointing at this ADR, and `expert_demo: False` until a future ADR attaches audit-tour-equivalent reports."* ADR-0100 §Invariant is the same sentence with `physics` / `adr-0100` substituted.

  Behind that sit ADR-0091's nine predicates (§Validation Semantics), of which the load-bearing ones for `reasoning-capable` are #5 (≥8 reviewed chains per claimed operator family), #6 (≥3 intent shapes), and #7 (*"Every `eval_lanes` entry has `dev`, `public`, and `holdout` **paths**"*).

- **Measurement performed:** all of the following run by this audit at `cbfc8ccb`.
  1. `uv run core capability ledger` — live.
  2. `uv run pytest tests/test_adr_0097_mathematics_logic_ratification.py tests/test_adr_0100_0102_sibling_ratifications.py tests/test_domain_contract_predicates.py -q` → **79 passed in 12.45s**.
  3. `evaluate_domain_contract("en_mathematics_logic_v1" | "en_physics_v1")` → **P1–P9 all pass, `all_passed=True`** for both.
  4. `uv run core eval <lane> --split {dev,public,holdout} --json` for all four declared lanes of both domains.
  5. `core.capability.expert_demo._meets_thresholds` applied to the *live* metrics from (4).

- **Verdict: SPLIT — the ADRs' literal invariants are both FALSE at `cbfc8ccb`, while the tier they were reaching for is (nominally) exceeded; and the bar they cleared is confirmed to be non-empirical.**

  Three separate results, none of which is "the ADR is fine":

  **(a) The invariant text is materially false.** The ledger row for `mathematics_logic` reads `status: audit-passed`, `predicates.audit_passed: True`. ADR-0097 pinned `status: reasoning-capable` and `expert_demo: False`. Same for `physics`. Neither ADR carries a supersession or amendment note, although the corpus has the convention and uses it four ADRs later (ADR-0110 header: `**Supersedes (partially):** ADR-0107 §Decision`). The `reasoning_capable` *predicate* is `True` for both, which is the defensible reading — but it is not what either ADR wrote down. → `AA-A2.5-7`.

  **(b) The criterion is not empirical, by construction.** The `reasoning_capable` predicate in `core/capability/reporting.py:428-434` is:
  ```python
  reasoning_capable = (
      grounded                                            # manifest + checksum + mount_eligible
      and bool(claimed)                                   # a hard-coded DOMAIN_OPERATOR_CLAIMS entry exists
      and all(op_counts[op] >= op_required[op] for op in claimed)   # ≥8 chains per family
      and intent_shapes_present >= 3
      and holdout_present                                 # ← see below
  )
  ```
  **Not one term reads an eval result.** The sabotage test is decisive: delete every file under `evals/elementary_mathematics_ood/results/`, `evals/foundational_physics_ood/results/`, and `evals/inference_closure/results/`, and both ADRs' invariants emit byte-identically. The one term that *sounds* empirical, `holdout_present`, is `(_REPO_ROOT / "evals" / "cognition" / "holdouts" / "cases_plaintext.jsonl").exists()` (`reporting.py:421`) — one global file belonging to the *cognition* lane, identical for all five domains, referencing neither `mathematics_logic` nor `physics`. It is a constant wearing a predicate's name. → `AA-A2.5-2`, `AA-A2.5-3`.

  **(c) The lane evidence the ADRs point at has since gone red, and the ledger cannot see it.** `inference_closure` — the *composition* evidence lane declared by **both** manifests — fails at HEAD on all three splits:

  | split | `all_pass_rate` | threshold (`inference_shape`) | `overall_pass` | stored 2026-05-22 |
  |---|---|---|---|---|
  | dev | **0.20** | ≥ 0.95 | **False** | 1.0 / True |
  | public | **0.25** | ≥ 0.95 | **False** | 1.0 / True |
  | holdout | **0.6667** | ≥ 0.95 | **False** | 1.0 / True |

  Fed the live numbers, the promotion contract refuses:
  ```
  _meets_thresholds('inference_closure', <live public metrics>)
    → (False, "lane 'inference_closure' all_pass_rate=0.25 below threshold 0.95")
  ```
  It never sees them. `core/capability/reporting.py:102-108` `_latest_eval_result` globs `evals/<lane>/results/v1_<split>_*.json`, sorts lexicographically, and returns the **last stored file** — dated 2026-05-22. Public is worse today (0.25) than the state that caused ADR-0107 to *defer* the first promotion (`all_pass_rate=0.4`, quoted in ADR-0110 §Context). → `AA-A2.5-1`, `AA-A2.5-2`.

  So: the `reasoning-capable` claim these two ADRs made is intact *as they defined it*, because they defined it as a manifest-shape claim. The `audit-passed` rows that README publishes on top of them are not intact, because those are defined empirically and their evidence has rotted. **NO-GO on the ADRs' literal invariants; the underlying tier survives only on the technicality that it was never empirical to begin with.**

#### 3. Liveness / integration

**Call chain, traced.** `core capability ledger` → `core/cli_capability.py` → `core.capability.reporting.ledger_report()` → for `mathematics_logic`: `_manifest_for_pack("en_mathematics_logic_v1")` (`reporting.py:111-113`), `chain_report()` for operator/intent counts, `DOMAIN_OPERATOR_CLAIMS["mathematics_logic"]` (`core/capability/domains.py:47`), then the `reasoning_capable` conjunction at `reporting.py:428-434`, then `evaluate_expert_demo(...)` at `:453` fed by `_fetch_lane_split` → `_latest_eval_result` → **stored JSON files on disk**, then the status ladder at `:494-505`.

This path is live and reached: the ledger is a real CLI surface, `CLAIMS.md`'s Tier-1 domain roster is documented as generated from `ledger_report` (`MV-verification-evidence.md:20`), and `README.md` publishes the resulting table.

But the *serving* path is a different question, and the answer there is no. `en_mathematics_logic_v1` is **not** in `RuntimeConfig.DEFAULT_CONFIG.input_packs` (`core/config.py:13-28`) — the pack set `chat/runtime.py` actually mounts. The ratified pack is not loaded when CORE answers a question. Its ratification is a claim about a file, consumed by a reporting command and a README table.

**Sabotage test.** Three separate stubs, all measured or read directly from the code:

1. *Delete every result file under `evals/elementary_mathematics_ood/results/` and `evals/inference_closure/results/`.* → `reasoning_capable` is **unchanged** (`reporting.py:428-434` never reads them). The ADR-0097 invariant emits identically. `audit_passed` would flip (it does read them), but that is ADR-0110's claim, not ADR-0097's.
2. *Stub `_resolve_eval_lane_artifacts` to return `()`.* → **nothing changes anywhere.** The function is called at `domain_contract_predicates.py:542`, stored on the report, serialized in `as_dict()`, and consumed by exactly one test assertion (`tests/test_domain_contract_predicates.py:390-391`). No production consumer. And it is *already* reporting `exists: False` for all three splits of `elementary_mathematics_ood` and `inference_closure` (naming mismatch: it looks for `v1_<split>.json`, the lanes write `v1_<split>_<timestamp>.json`) with no effect on any verdict — the sabotage has effectively already happened and left no trace.
3. *Replace `holdout_present` with the literal `True`.* → **no domain's status changes**, because it is one global `evals/cognition/holdouts/cases_plaintext.jsonl` existence check shared by all five domains.

The mechanism that *is* load-bearing and *does* fire is narrow: the ≥8-chains-per-family and ≥3-intent-shapes counts. That is a real gate on a real file — but the file is 24 hand-authored subject–connective–object triples over a 16-word vocabulary, authored under the same ADR-0090 seed act, on the same date, as the bar they clear.

**Liveness axis: live (reporting only) / wired-but-unreached (serving)** — the ledger row is genuinely computed and published; the ratified pack it certifies is never mounted by the serving runtime, and the eval-lane half of the ADR's own evidence list is provably inert (sabotage tests 1 and 2).

#### 5. Build fidelity — does the code match the decision?

The manifest block matches byte-for-byte. Three specific divergences:

#### 7. Necessity / generality

1. **Necessity.** The *ledger* is necessary — a system that makes capability claims needs a single place where those claims are computed from artifacts rather than asserted in prose, and `ledger_report` is that place. **This ADR** is not: it is one row's worth of data (nine manifest fields plus a provenance string) elevated to a decision record. The system loses nothing if ADR-0097's content lives in a domain-ratification register instead of an ADR. What *would* be lost by deleting the manifest block is the row itself — so the artifact is necessary; the ADR-as-container is not.

2. **Reducibility.** No L0/L1 algebra or field operator does this — the contract is a documentation-layer construct with no geometric content. But there is a real reducibility *within* the capability layer: the `reasoning_capable` conjunction (`reporting.py:428-434`) and the nine ADR-0091 predicates (`domain_contract_predicates.py`) are **two independent implementations of overlapping checks that never consult each other**. `reasoning_capable` re-derives chain counts and intent shapes itself; it never reads `report.all_passed`. A pack could fail P8 (reviewers unresolvable) and still emit `status: reasoning-capable`, because the status ladder does not gate on the predicate report. Two validators, one claim, no cross-check. → `AA-A2.5-9`.

3. **Extensibility.** ADR-0097's construction *is* the generalization — ADR-0100 §Context says so explicitly, and 0101/0102 follow. The pairing candidate is therefore not "generalize 0097" but "collapse 0097+0100+0101+0102+0103 into one ratification register with five rows." Five ADRs whose combined novel content is five manifest blocks and five invariant sentences. → `AA-A2.5-14`, feeder for `22-consolidation-report.md`.

**Necessity/generality axis: generalization-candidate** — the mechanism is sound and already general; the ADR-per-instance packaging is the redundancy, and the internal duplication between the status ladder and the nine predicates is a second, tighter consolidation target.

## 3. Stack-level synthesis

**Internal consistency.** The two ADRs agree completely.
